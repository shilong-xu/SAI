# 邮件分类与待办判定技能（mail-todo）

本技能由 **EmailAgent（邮件中枢）** 在收到邮件后启用，解决两件事：

1. **这封邮件是什么类型？**（任务 / 事项 / 会议 / 回信）
2. **要不要登记为待办事项？** 要就给出可直接落库的 `title / type / content`。

> 本技能只做**判定**，不直接操作数据。判定结果交给 **TodoAgent（待办子智能体）** 通过 `save_todo` 落库。

## 触发条件
- 邮件流水线（消息以 `[邮件流水线-无人值守模式]` 开头）投递来一封新邮件；
- 用户要求「看看新邮件里有没有要做的事 / 把邮件里的待办整理出来 / 帮我盯着邮件」等。

## 一、类型判定（先定类型）

按**主题优先、正文印证**的顺序判断，主题里出现强特征词即可先定初判，再用正文确认：

| 类型 | 判定特征（主题 / 正文） | 典型例子 |
| --- | --- | --- |
| **会议** | 主题含 会议 / 例会 / 评审 / 对齐 / 邀请 / 日程 / 时间地点，或正文给出**具体时间 + 参与方 / 链接** | 「周四 14:00 需求评审」「会议邀请：季度复盘」 |
| **回信** | 明确**需要我方回一封邮件**：对方在等答复（咨询、确认、催办、报价、请求授权），或主题含 回复 / 答复 / Re / 请确认 | 「麻烦确认下报价」「关于上周方案的答复」 |
| **任务** | 要求我方**产出一个交付物**（文档、代码、修复、上线、报告、数据），通常带期限或验收标准 | 「请在周五前提交测试报告」「修复登录超时问题」 |
| **事项** | 需要**跟进 / 知悉 / 留痕**，但没有明确交付物：通知、变更公告、账单/续费提醒、审批结果、进度同步 | 「服务续费提醒」「系统升级通知」「审批已通过」 |

判定规则：
- **可多标签取主**：一封邮件既约了会又要求交付物时，取**最需要动作**的那个（一般 任务 > 会议 > 回信 > 事项）。
- `会议` 优先看**时间和参与方**是否明确；只有「有空聊聊」这类无时间无议题的寒暄，按 `事项`。
- `回信` 的判定关键在**对方是否在等我方的回复**；我方向对方发的通知类邮件不算。
- 拿不准时取 `事项`（最轻量、最不容易误导）。

## 二、是否需要登记为待办

**应当登记**（满足其一即登记）：
- 有明确动作要求（做事、交付、修复、提交、审批、回复）；
- 有明确时间点或期限（会议、截止日、到期日、续费日）；
- 需要我方后续跟进，不登记就会遗忘（等对方回复、等第三方处理、需线下确认）；
- 涉及金额、合同、账号安全、生产环境、对外承诺 —— 一律登记（漏了代价高）。

**不登记**（满足其一即跳过）：
- 广告营销、推广、拉群、垃圾邮件；
- 纯通知且**不需要我方任何动作**（如「您已成功订阅」「本周行业资讯」）；
- 系统自动回执 / 退信 / 送达通知（如「自动回复：我休假中」）；
- 验证码、激活链接、密码重置等一次性操作邮件（时效极短，登记无意义）；
- 内容为空或只有附件而无正文说明、无法判断意图 —— 登记为 `事项` 并在 `content` 里写明「仅有附件，待人工确认」，**不要凭空编造诉求**。

> 同一封邮件**最多登记一条**待办；一封邮件里确实有多件互不相干的事，才拆成多条。

## 三、字段映射（登记时怎么填）

- **title（标题，必填）**：一句话说清「要做什么」，20 字内最佳，不要照抄长主题。
  - ✅「回复张三关于报价的确认邮件」「周四 14:00 需求评审」「提交 V2 测试报告」
  - ❌「关于上周讨论的后续事宜」（太糊）、「【系统通知】服务将于…」（照抄原文）
- **type（类型，必填）**：上面判定的四种之一，**落库为数字 code**：`1`=任务 / `2`=事项 / `3`=会议 / `4`=回信。
  - 调用 `save_todo` 时写数字或中文标签都可以（工具内部会归一），但**对用户描述时统一用中文**，不要直接说「类型 3」。
- **content（正文，Markdown，建议填）**：让**没读过原邮件的人也能直接执行**。至少包含：
  - 来源：`来自 <发件人> 的邮件《<主题>》（邮件ID=<id>）`
  - 要做什么 / 关键要求
  - 时间点 / 期限（原文有就写，没有就不写，不要编）
  - 关键信息（单号、金额、链接、附件名）
- 正文原文很长时**只提炼要点**，不要把整封邮件粘贴进去。

## 四、登记动作（交给 TodoAgent）

判定为需要登记后，**显式请求主 Agent 派发 TodoAgent**，把 `title / type / content` 三项一并给出，例如：

> 请使用 TodoAgent 子智能体保存这条待办：标题「回复张三关于报价的确认邮件」，类型 4（回信），内容「来自 zhang@x.com 的邮件《请确认报价》（邮件ID=42）；需在今天下班前回复是否接受 8.5 折的报价」。

- **先查后写**：TodoAgent 保存前会按标题查重；如已存在同标题待办，不要重复创建，也不要改标题绕过查重。
- **只登记、不发送**：不要把「回信」这件事直接做成「把邮件发出去」；回信本身是待办内容，实际发送须用户明确确认（见 mail 技能 §四）。

## 五、状态维护

邮件中明确出现「已完成 / 已处理 / 已取消」的事（如「之前的报价问题已经解决了」「该会议已取消」）时：
- 先让 TodoAgent **查询**是否存在对应待办；
- 命中后再把状态改为已完成（`update_todo_status`）；
- **查不到就不要凭感觉新建一条「已完成」的待办**。

## 六、边界

- **无人值守不发送**：邮件流水线场景只做分类与待办登记，**绝不发送任何邮件**；
- **不臆造**：时间、金额、人名、结论必须来自邮件原文；原文没有的就不写；
- **隐私**：不把邮件里的账号、验证码、密钥等敏感信息写进待办正文；
- **宁缺勿滥**：拿不准是否登记时，倾向于登记为 `事项`；但明确的营销/回执/验证码一律不登记。
