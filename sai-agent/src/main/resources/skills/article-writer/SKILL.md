# 文章编写与入库技能（article-writer）

本技能处理两类跟"文章"相关的诉求，但**无论哪一类，都必须在最后询问用户是否存储，且只有用户确认后才调用 `save_knowledge` 落库**（禁止自动写入）。

## 触发条件
- 用户要你**写/编/创作/生成**一篇文章（给主题、给方向、给素材都算）；
- 用户**上传或粘贴了一篇现成文章**，希望你分析、提炼、润色或存档。

---

## 一、从头编写文章（用户要你写）

### 第 1 步：澄清需求（信息不足时先问，不要凭空猜）
至少搞清楚这几点，缺哪样就简短问哪样（可一次把问题合并问，别一句一句挤）：

- **内容与主题**：要写什么？核心论点 / 素材 / 背景是什么？
- **写作方向 / 角度**：偏科普、观点、教程、故事、报告、营销文案？想要什么立场或切入点？
- **目标读者与语气**：给谁看？正式 / 口语 / 轻松？
- **关键词**：用户有没有指定要覆盖的关键词？没有就先按主题拟 3~8 个，后续用于检索。
- **篇幅与格式**：大概多长？要不要分章节、加小标题、配结构？

> 用户没空细说时，按最合理的默认假设去写也行，但**动笔前用一两句话把你的理解摆出来**，让对方有机会纠正。

### 第 2 步：撰写文章
- 按澄清后的方向产出完整文章；长文用清晰的标题层级与段落组织。
- 行文本身不受"简短优先"约束——这是交付物，该展开就展开。
- 写完后，在文末**附上你提取的「关键词」清单**（3~8 个，逗号分隔），方便用户确认。

---

## 二、分析用户提供的文章（用户上传/粘贴现成文章）

当用户直接给了一篇文章（上传文件或粘贴正文）：

1. **通读并提炼**：给出一句话摘要 + 3~5 个要点；
2. **提取关键词**：从正文抽取 3~8 个能概括主题的核心关键词（这是后续存入知识库、用于向量 + 模糊检索的关键字段）；
3. **可选建议**：结构、逻辑、表达上可改进之处（用户没要求就不硬给）；
4. 把提炼出的**标题建议 + 关键词**明确列出来，供用户确认存储时用。

---

## 三、收尾：询问是否存储（本技能最关键的一步）

文章产出 / 分析完成后，**必须主动询问用户是否存入「知识库」**，例如：

> "这篇要不要存进知识库？存的话我就用上面这些关键词建索引，以后能直接检索到。"

- **用户确认存储（"存"/"保存"/"好的"等明确肯定）**：调用 `save_knowledge` 工具（对应 `knowledge_base` 表，前端「知识库」页面可见、可向量检索），参数映射：
  - `name`：文章标题（用你拟的或用户给的，必填）；
  - `keyword`：提取出的关键词，逗号分隔（建议填，否则检索能力退化）；
  - `content`：文章**完整正文**（必填，不要把正文截断；如有来源，可于正文开头注明「来源：xxx」）。
- **用户拒绝存储**：不调用任何工具，正常结束即可，不要反复追问。

### 约束
- **绝不在用户确认前调用 `save_knowledge`**；也不要把"已写入知识库"这类后端动作写进给用户的回复——落库成功后只给一句结论式反馈（如"已存入知识库，之后能检索到"）。
- 存储是为"以后可检索复用"服务：关键词质量直接决定检索效果，宁可少而准、不要多而杂。
- 文章正文较长时，`content` 传完整文本，不要只存摘要。
